필수만 정리. 칸 이름 · 자료형 · API 목록은 아직 확정 전이라 정하면 이 문서에 추가한다.

## 프론트 — 보호자 앱 (Android)

| 할 일 | 내용 | 비고 |
|---|---|---|
| 화면 만들기 | 첫 실행 · 지도 · 장소 카드와 상세 · 방문 확정 · 다녀온 뒤 기록 · 측정 · 설정 (선택 기능 화면은 만들지 않음) |  |
| 지도 | 지도 SDK 연동, 장소 표시(진하기 3단계 + 글자, 추정 · 정보 부족 상태), 범례 |  |
| 위치 | 위치 권한, 현재 위치, 측정 장소와의 거리 |  |
| 마이크 입력 | 마이크 권한, AudioRecord로 16kHz 모노 소리 흐름 받기. 파일로 저장하는 코드는 만들지 않음 | 샘플레이트가 맞지 않으면 결과가 엉망이 됨 |
| 폰 안의 AI | YAMNet(TFLite)으로 약 1초 단위 추론, 상위 라벨과 확신도 표시 | 영상 AI 장면 |
| 측정 처리 | 30초 카운트다운, 화면 꺼짐 방지, 앱 이탈 시 취소, 소리 크기(dB) 계산, 결과 요약 |  |
| 측정 결과 전송 | 상위 라벨 · 확신도 · 크기 · 시각 · 장소 · 기기 모델 · 기기 ID를 측정 표에 저장 | 원본 소리 · 음성 임베딩은 보내지 않음 |
| 맞춤 점수 계산 | 서버가 계산해 둔 요소별 점수에 아이 가중치를 곱해 바로 다시 계산 | 스위치를 켜면 서버를 거치지 않고 즉시 바뀌게 |
| 권고 문구 · 바뀐 이유 | 예측 데이터로 "14시 이후가 무던합니다" 문구와 맞춤으로 바뀐 이유 만들기 |  |
| 예측 그래프 | 1시간 단위 막대. 지난 시간 진하게 · 앞으로 옅게 · 정보 부족 빗금 |  |
| 기기 ID | 첫 실행 때 만들어 기기에 보관하고 모든 저장에 사용 | 로그인 대신 |
| 방문 | 방문 확정 저장, 방문 예정 배너, 다녀온 뒤 기록 저장 |  |
| 사업장 무던한 시간 표시 | 사업장 무던한 시간 표를 읽어 지도 표시와 장소 상세에 보여주기. 지금 요일 · 시각과 비교해 "운영 중" 판단 |  |
| APK 빌드 | 실기기에 설치해서 확인 | 처음에 빈 앱으로 한 번 끝까지 해볼 것 |

## 백 — 보호자 앱

| 할 일 | 내용 | 비고 |
|---|---|---|
| 데이터 통로와 권한 | Supabase API로 앱이 표를 읽고 쓰게 열기. 기기 ID 기준으로 자기 프로필과 방문만 읽고 쓰도록 제한 | 서버 코드를 따로 짜지 않고 Supabase 기능으로 |
| 혼잡도 수집 | 서울시 실시간 도시데이터에서 1시간마다 현재 혼잡도와 향후 12시간 예측값을 저장 | 예약 실행 (예: GitHub Actions 또는 클라우드 서버) |
| 소리 묶음 적용 | 측정에 담긴 원본 라벨을 소리 종류 5개로 묶음 | 묶음표를 나중에 고쳐도 지난 측정을 다시 계산할 수 있음 |
| 감각부하 점수 계산 | 측정마다 소리 · 혼잡 요소별 점수와 기본 점수(0~100) | 요소별 점수를 따로 저장해야 앱에서 맞춤 계산 가능 |
| 시간대별 예측 | 장소마다 오늘 1시간 단위 예측. 같은 요일 · 시간의 과거 측정 평균에 혼잡도 예측값으로 보정. 같은 요일 측정이 없으면 평일 / 주말 평균 | 제안서의 "경량 시계열 예측" |
| 상태 판정 | 시간마다 단계 / 추정 / 정보 부족 판정 | 측정 3건 기준 |
| 계산 주기 | 점수 계산과 예측을 정해진 간격(예: 10~15분)마다 다시 실행 | 측정 직후 바로 반영하려면 계산을 부르는 작은 API가 따로 필요 |

## DB — 보호자 앱 (Supabase)

| 표 | 담는 것 | 쓰는 화면 | 비고 |
|---|---|---|---|
| 장소 | 이름 · 업종 · 주소 · 좌표 · 속한 혼잡도 지역 | 지도, 장소 카드 · 상세 | 10~15곳 직접 입력 |
| 기기 프로필 | 기기 ID · 고른 자극과 순서 · 현재 가중치 | 첫 실행, 설정, 맞춤 | 아이 이름 · 나이 · 진단명 칸 없음 |
| 측정 | 장소 · 기기 ID · 기기 모델 · 측정 시각 · 상위 라벨과 확신도 · 크기 | 측정, 장소 상세 | 원본 소리 · 임베딩 칸 없음 |
| 소리 묶음표 | YAMNet 라벨 → 소리 종류 5개 | 측정, 점수 계산 | 확인 필요: "안내방송"과 딱 맞는 라벨 이름이 있는지 모름 |
| 혼잡도 | 지역 · 기준 시각 · 대상 시각 · 혼잡도 · 실측 / 예측 구분 | 점수 계산, 장소 상세 | 1시간마다 쌓임 |
| 시간별 예측 | 장소 · 날짜 · 시각 · 요소별 점수 · 기본 점수 · 상태 · 측정 수 | 지도, 장소 카드 · 상세, 방문 확정 | 앱은 대부분 이 표를 읽음 |
| 방문 | 기기 ID · 장소 · 방문 예정 시각 · 기록(괜찮음 / 힘듦) | 방문, 지도 배너 |  |
| 설정값 | 단계 기준선 · 정보 부족 기준(3건) · 순위별 가중치 | 점수 계산, 맞춤 | 값을 바꿀 때 앱을 다시 빌드하지 않도록 |

## DB — 사업장 등록 웹

| 표 | 담는 것 | 쓰는 화면 | 비고 |
|---|---|---|---|
| 사업장 무던한 시간 | 장소 · 요일 · 시작 · 끝 · 하는 조치 · 수정 시각 | 사업장 웹에서 쓰고, 앱 지도 · 장소 카드 · 상세에서 읽음 | 한 가게에 여러 줄. 장소 표는 앱용을 그대로 씀 |

## DB에 처음 직접 넣을 데이터

| 데이터 | 내용 | 비고 |
|---|---|---|
| 장소 10~15곳 | 이름 · 업종 · 주소 · 좌표 · 혼잡도 지역 |  |
| 소리 묶음표 | YAMNet 라벨 목록을 열어 소리 종류 5개로 나눠 넣기 |  |
| 설정값 첫 값 | 단계 기준선, 순위별 가중치 (첫 측정 데이터를 보고 조정) |  |

## 계산 규칙 (현재 설계)

| 항목 | 규칙 |
|---|---|
| 점수 나누기 | 서버는 요소별 점수(소리 · 혼잡)를 따로 저장. 앱이 아이 가중치를 곱해 맞춤 점수를 즉시 계산 (스위치를 켜면 서버를 거치지 않고 바로 바뀌게) |
| 소리 묶음 | 앱은 YAMNet 원본 상위 라벨을 보내고, 서버가 소리 종류 5개로 묶음. 묶음표를 고치면 지난 측정도 다시 계산 가능 |
| 시간대별 예측 | 같은 요일 · 시간의 과거 측정 평균 + 혼잡도 예측값으로 보정. 같은 요일 측정이 없으면 평일 / 주말 평균 |
| 상태 판정 | 측정 3건 이상 → 단계 (무던 · 보통 · 붐빔) / 3건 미만이지만 혼잡도 있음 → 추정 / 둘 다 없음 → 정보 부족 |
| 계산 주기 | 10~15분마다 다시 계산. 측정 직후 바로 반영하려면 계산을 부르는 작은 API가 따로 필요 |

## 보고서용 분석 (앱과 별개, Python)

| 할 일 | 내용 | 비고 |
|---|---|---|
| AI 분류 정확도 | 녹음을 들으며 사람이 표시한 소리 종류와 YAMNet 결과를 비교 | 가장 먼저. 안 되면 전체 재설계 |
| 기종별 차이 | 아이폰 · 안드로이드로 같은 장소를 동시에 측정해 차이 계산 | 실험용 녹음은 분석 후 삭제 |
| 지역 ↔ 가게 비교 | 측정 시각의 지역 혼잡도와 가게 실측 점수의 관계 계산 | 낮게 나와도 유효한 결과 |

보호자 섭외 없이 두 사람이 할 수 있는 검증이다.
