# 일정 — 10/30(금) 제출까지

## 데모 영상 장면 (여기서 역산)

영상에 안 나오는 기능은 10/30까지 안 만들어도 된다.

| 구간 | 장면 | 역할 |
|---|---|---|
| 0:00~0:30 | 아이가 마트에서 감각 과부하로 힘들어하고 가족이 외출을 포기하는 상황 | 문제 제기 |
| 0:30~1:00 | 지도를 열면 주변 장소가 무던함 · 보통 · 붐빔으로 (색이 아니라 진하기) | 서비스 진입 |
| 1:00~1:40 | 장소를 누르면 오늘 시간대별 그래프 + "오늘은 14시 이후가 무던합니다" | 핵심 출력 |
| 1:40~2:20 | 현장에서 측정 → 소리 종류와 확신도가 실시간으로 뜨고 점수에 반영 | AI 장면 |
| 2:20~3:00 | 아이 민감 요인을 바꾸니 같은 장소 점수와 권고 시간이 달라짐 | 핵심 주장 |
| 3:00~3:20 | 사업장 웹에서 무던한 시간 등록 → 앱 지도에 표시 | 사업장 참여 |
| 3:20~3:40 | 측정이 부족한 장소는 "추정" / "정보 부족"으로 표시 | 신뢰성 |
| 3:40~4:10 | 검증 결과 — AI 분류 정확도, 기종별 차이, 지역 ↔ 가게 비교 | 정량 근거 |

## 주차별

| 기간 | 목표 | 할 일 |
|---|---|---|
| ~10/11 (Phase 0) | 막힐 것부터 치우기 | YAMNet 녹음 실험 (안내방송과 음악을 구분하는가), 빈 앱 APK 실기기 설치, API 키 · Supabase 프로젝트, 성과보고서 양식 확인, 역할 확정 |
| 10/12~10/18 (1주) | 측정이 되고 지도에 장소가 보인다 | YAMNet TFLite 앱 탑재, 측정 화면, 지도 + 장소 10~15곳, 혼잡도 수집 batch, DB 표 확정, 주말 현장 측정 1차 (아이폰 · 안드로이드 동시 측정) |
| 10/19~10/25 (2주) | 영상 장면이 다 나온다 | 점수 계산 · 시간대별 예측 · 상태 판정, 장소 카드 그래프, 우리 아이 맞춤, 방문 확정 · 기록, 사업장 웹, 현장 측정 2차 (다른 시간대), 검증 분석 |
| **10/25** | **기능 동결** | 안 들어간 건 버리고 성과보고서 "개선방안"에 쓴다 |
| 10/26~10/27 | 성과보고서 | AI 접근방법(YAMNet · TFLite · 지수 계산식), 결과 해석(검증 숫자), 한계(측정 장소 수 · 기종 수 · 지역 단위 차이) |
| 10/28 | 데모 영상 | 장면별로 찍어서 붙이기. 측정 장면은 실제 매장에서 |
| 10/29 | 마무리 | 참가신청서 + 대표자 서명, 최종 APK를 다른 기기에서 설치 확인, 양식 재확인 |
| **10/30(금)** | **제출** | 주말 답변 불가라 금요일에 보낸다 |

## 검증 (보고서용)

| 검증 | 방법 | 보고서에 쓰는 문장 예 |
|---|---|---|
| AI 분류 정확도 | 녹음을 들으며 사람이 표시한 소리 종류와 YAMNet 결과 비교 | "N개 구간 중 n%에서 사람 판단과 일치" |
| 기종별 차이 | 아이폰 · 안드로이드로 같은 장소를 동시에 측정 | "동일 장소 동시 측정 시 평균 n% 편차" |
| 지역 ↔ 가게 비교 | 측정 시각의 지역 혼잡도와 가게 실측 점수의 관계 | 낮게 나와도 "지역 단위로는 부족하고 실측이 필요하다"는 유효한 결론 |
